# Issue #6006 — DevUI approval response discriminator not recognized

- Repo: microsoft/agent-framework · [issue #6006](https://github.com/microsoft/agent-framework/issues/6006)
- Category: **AF-specific** — proposal for once MAF consumes our packages

## Summary
DevUI reaches the human-in-the-loop approval state for a workflow exposed as an agent, but clicking Approve sends a `function_approval_response` item that MAF's OpenAI Responses hosting layer rejects during JSON deserialization. The failure is in DevUI/OpenAI-hosting approval-resume handling, not in the AG-UI wire event definitions.

## What our packages already provide
- `AGUI.Hosting.AspNetCore` converts an incoming AG-UI `resume` entry with a `toolCall` payload into MEAI `ToolApprovalRequestContent` plus `ToolApprovalResponseContent`, so a downstream `FunctionInvokingChatClient` can resume the approved call (`sdks/dotnet/src/AGUI.Hosting.AspNetCore/RunAgentInputExtensions.cs:60`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/RunAgentInputExtensions.cs:71`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/RunAgentInputExtensions.cs:147`).
- The server stream converter already turns `ToolApprovalRequestContent` into AG-UI `TOOL_CALL_*` events plus a `RUN_FINISHED` interrupt carrying approval metadata (`sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:234`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:247`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:271`).
- `AGUI.Client` converts MEAI `ToolApprovalResponseContent` back into AG-UI `resume` payloads (`sdks/dotnet/src/AGUI.Client/AGUIChatClient.cs:398`, `sdks/dotnet/src/AGUI.Client/AGUIChatClient.cs:424`, `sdks/dotnet/src/AGUI.Client/AGUIChatClient.cs:439`).

## What remains MAF-side
MAF still owns DevUI's Responses REST schema and the OpenAI-hosting deserializer that currently does not recognize `function_approval_response`. Our SDK does not parse DevUI `CreateResponse` input items, implement the DevUI approval button endpoint, or own workflow-as-agent approval routing.

## Proposal (once MAF consumes our packages)
1. In `Microsoft.Agents.AI.Hosting.OpenAI`, add a `function_approval_response` item model/converter case so DevUI approval posts deserialize instead of returning 400.
2. Translate that item into MEAI approval-resume content (`ToolApprovalResponseContent`, paired with the original request/call id) before invoking the workflow-as-agent pipeline.
3. When the AG-UI endpoint is used, pass the AG-UI request through `RunAgentInputExtensions.ToChatRequestContext(...)`; its existing resume bridge will handle AG-UI-native clients.
4. Add a DevUI regression test that posts a `CreateResponse` containing `function_approval_response` and verifies the workflow resumes.
