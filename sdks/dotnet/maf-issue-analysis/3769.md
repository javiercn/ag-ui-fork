# Issue #3769 — Decouple AG-UI protocol from transport

- Repo: microsoft/agent-framework · [issue #3769](https://github.com/microsoft/agent-framework/issues/3769)
- Category: **Integration-pkg — already fixed/covered**

## Summary
The issue asks for AG-UI translation to be usable without a mandatory HTTP/SSE topology, so callers can pipe protocol events over WebSockets, gRPC, MQTT, or another transport.

## Fix in our SDK
Server-side translation is an extension that returns `IAsyncEnumerable<BaseEvent>` (`src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:36-39`), independent of SSE framing. Client transport is also abstracted behind public `IAGUITransport.SendAsync(...) -> IAsyncEnumerable<BaseEvent>` (`src/AGUI.Client/IAGUITransport.cs:10-18`), with the public API listed in `src/AGUI.Client/PublicAPI.Unshipped.txt:6-9`.

## Validating test
Existing test: `tests/AGUI.Hosting.AspNetCore.UnitTests/ChatResponseUpdateAGUIExtensionsTest.cs:18` (`EmptyStream_EmitsRunStartedAndRunFinished`) validates the converter yields protocol events directly; the helper enumerates `updates.AsAGUIEventStreamAsync(...)` without HTTP/SSE at `tests/AGUI.Hosting.AspNetCore.UnitTests/ChatResponseUpdateAGUIExtensionsTest.cs:1349`.

## Notes
MAF can use the hosting converter as a transport-agnostic event generator and the client transport abstraction for non-HTTP event sources; SSE remains only one possible wrapping layer.
