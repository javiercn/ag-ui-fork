# Issue #4869 — AGUIChatClient sets ConversationId despite being stateless

- Repo: microsoft/agent-framework · [issue #4869](https://github.com/microsoft/agent-framework/issues/4869)
- Category: **Integration-pkg — open design decision (characterization test added)**

## Summary
`AGUIChatClient` is stateless (it sends full history each turn). But it echoes the
caller-supplied `ConversationId` back on returned updates. `AsAIAgent` wrappers interpret a
returned `ConversationId` as "the server is stateful" and then send only deltas on the next
turn — which breaks against a stateless AG-UI server.

## Finding (our SDK)
The client strips `ConversationId` from the options it passes inward (so full history is sent)
but re-applies it to the outgoing updates:
- captures it: `src/AGUI.Client/AGUIChatClient.cs:73-79`
- re-applies it on the returned update: `src/AGUI.Client/AGUIChatClient.cs:165-173`
This is intentional thread-id round-tripping, so whether to change it is a **design decision**,
not a clear-cut bug.

## Validation
- Test: `tests/AGUI.Client.UnitTests/MafIssueClientValidationTests.cs` →
  `GetStreamingResponse_EchoesCallerConversationId`
- Result: **PASS — characterizes current behavior** (a caller-supplied `ConversationId` is
  echoed back on the updates). Left active as a regression guard for the current contract.

## Proposed step (not implemented — design decision)
Decide whether a stateless `AGUIChatClient` should suppress `ConversationId` on returned
updates (so `AsAIAgent` keeps sending full history), or whether the round-trip should stay and
`AsAIAgent` integration be documented/adjusted. Resolve before undrafting.
