# Issue #3365 — AGUIMessage to ChatMessage transformation drops tool MessageId

- Repo: microsoft/agent-framework · [issue #3365](https://github.com/microsoft/agent-framework/issues/3365)
- Category: **Integration-pkg — already fixed/covered**

## Summary
The issue reports that `AGUIMessage.AsChatMessages()` maps an `AGUIToolMessage` to a `ChatMessage` with the correct role and `FunctionResultContent`, but fails to copy `AGUIToolMessage.Id` into `ChatMessage.MessageId`.

## Fix in our SDK
`src\AGUI.Abstractions\Extensions\AGUIChatMessageExtensions.cs:94-104` preserves the AG-UI message id in the tool-message branch:

```csharp
yield return new ChatMessage(role, contents)
{
    MessageId = message.Id
};
```

## Validating test
Added (pending central run): `tests\AGUI.Abstractions.UnitTests\MafIssueFixedTests_3365.cs:9-25`, method `AsChatMessages_ToolMessage_PreservesMessageId`, validates the exact reported scenario and asserts `ChatMessage.MessageId == "msg1"`.

## Notes
This is the same underlying fix as issue #4342. MAF should use the shared `AGUI.Abstractions` conversion path rather than duplicating the older mapping.
