# Issue #6511 — Tool call error in AGUI mapping with WorkflowAsAgent/session

- Repo: microsoft/agent-framework · [issue #6511](https://github.com/microsoft/agent-framework/issues/6511)
- Category: **Integration-pkg — already fixed/covered**

## Summary
The issue reports a WorkflowAsAgent/session scenario where a non-JSON tool result like `Expense report ... approved` is surfaced as `TOOL_CALL_RESULT` and the AG-UI client crashes while trying to parse it as JSON.

## Fix in our SDK
The AF-specific WorkflowAsAgent/session orchestration is outside this SDK, but the AG-UI client bug is avoided here: `ToolCallResultEvent` content is a string (`src/AGUI.Abstractions/Events/ToolCallResultEvent.cs:20-21`), and `EventStreamConverter` passes that string directly into `FunctionResultContent` (`src/AGUI.Client/Internal/EventStreamConverter.cs:255-258`). Hosting also preserves string function results (`src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:383-390`).

## Validating test
Added (pending central run): `tests/AGUI.Client.UnitTests/MafIssueFixedTests_6511.cs:11` (`AGUIChatClient_WorkflowToolCallResultWithPlainTextContent_DoesNotThrowJsonException`) validates a workflow-style plain-text tool result is accepted as a raw string.

## Notes
MAF still owns any WorkflowAsAgent/session mapping details, but by consuming `AGUI.Client` it avoids the JSON-parse crash for non-JSON `TOOL_CALL_RESULT` content.
