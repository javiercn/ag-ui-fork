# Issue #5614 — Convert MAF AG-UI ASP.NET Core hosting package to .NET Standard

- Repo: microsoft/agent-framework · [issue #5614](https://github.com/microsoft/agent-framework/issues/5614)
- Category: **AF-specific** — proposal for once MAF consumes our packages

## Summary
The issue asks for `Microsoft.Agents.AI.Hosting.AGUI.AspNetCore` to support `netstandard2.0`/`netstandard2.1` for legacy consumers. The package named in the issue is MAF's in-tree ASP.NET Core AG-UI hosting package; our replacement packages split protocol/client from ASP.NET Core hosting.

## What our packages already provide
- The shared SDK targets `net10.0;net9.0;net8.0` plus `netstandard2.0;net472` by default (`sdks/dotnet/Directory.Build.props:14`, `sdks/dotnet/Directory.Build.props:15`).
- `AGUI.Abstractions` inherits that default target set and only references MEAI abstractions/System.Text.Json (`sdks/dotnet/src/AGUI.Abstractions/AGUI.Abstractions.csproj:4`, `sdks/dotnet/src/AGUI.Abstractions/AGUI.Abstractions.csproj:8`).
- `AGUI.Client` also inherits the broad target set and exposes an `IAGUITransport` abstraction for non-ASP.NET transports (`sdks/dotnet/src/AGUI.Client/AGUI.Client.csproj:4`, `sdks/dotnet/src/AGUI.Client/IAGUITransport.cs:10`, `sdks/dotnet/src/AGUI.Client/IAGUITransport.cs:18`).
- `AGUI.Hosting.AspNetCore` intentionally targets only `$(TargetFrameworksCore)` and takes a `Microsoft.AspNetCore.App` framework reference (`sdks/dotnet/src/AGUI.Hosting.AspNetCore/AGUI.Hosting.AspNetCore.csproj:4`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/AGUI.Hosting.AspNetCore.csproj:13`).

## What remains MAF-side
MAF must decide how its legacy-facing package should be shaped after replacing the in-tree package. ASP.NET Core endpoint hosting cannot be made `netstandard2.0` without removing ASP.NET Core runtime dependencies; any legacy-compatible surface must live in protocol/client abstractions or a non-ASP.NET adapter.

## Proposal (once MAF consumes our packages)
1. Replace MAF's in-tree protocol types with references to `AGUI.Abstractions` for legacy-compatible protocol models.
2. For .NET Standard consumers, expose guidance or a MAF package that depends on `AGUI.Abstractions`/`AGUI.Client` and lets callers provide their own `IAGUITransport`.
3. Keep MAF's ASP.NET Core endpoint package as `net8.0+` and depend on `AGUI.Hosting.AspNetCore` only there.
4. Document that `MapAGUI`-style server endpoints require ASP.NET Core, while protocol/client use can target legacy TFMs.
