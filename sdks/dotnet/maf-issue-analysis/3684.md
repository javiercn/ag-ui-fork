# Issue #3684 — UsageContent not returned in AG-UI stream

- Repo: microsoft/agent-framework · [issue #3684](https://github.com/microsoft/agent-framework/issues/3684)
- Related: #3520, #3752 (same topic)
- Category: **Integration-pkg — by design (extensibility), not a default mapping**

## Summary
Same topic as #3520: `UsageContent` emitted by the model is not surfaced over AG-UI by default.

## Resolution — by design, via extensibility
Usage is not an AG-UI protocol concept, so per our guiding principle it is surfaced through
extensibility rather than a default mapping. The **preferred** path is to wrap the
`IChatClient`/`AIAgent` and emit a `CustomEvent`/`RawEvent` via
`ChatResponseUpdate.RawRepresentation` (as the shipped `Step06_RawEvents`
`UsageRawEventsChatClient` does). An `AGUIStreamOptions.MapContent(...)` mapper is a secondary
seam aimed at framework integrators (e.g. MAF). See [3520.md](3520.md) for the full write-up.

## Validation
By design — no dedicated test (snippet in [3520.md](3520.md)); the wrapping-client path is
exercised by the Step06 sample tests.

## Proposed step
No framework change — document the extensibility recipes.
