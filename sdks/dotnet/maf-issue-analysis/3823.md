# Issue #3823 — Workflow-as-agent middleware receives null session under AG-UI

- Repo: microsoft/agent-framework · [issue #3823](https://github.com/microsoft/agent-framework/issues/3823)
- Category: **AF-specific** — proposal for once MAF consumes our packages

## Summary
When a MAF workflow is converted into an agent and served through AG-UI, middleware attached to that workflow-as-agent sees `AgentSession? session` as `null`. Middleware attached to the individual agents inside the workflow sees a session, indicating the gap is in MAF's AG-UI/workflow session plumbing.

## What our packages already provide
- `RunAgentInput` carries `threadId`, the AG-UI conversation identifier MAF can map to a session (`sdks/dotnet/src/AGUI.Abstractions/Context/RunAgentInput.cs:16`).
- `ToChatRequestContext` adapts AG-UI input into MEAI messages/options and preserves the original request in `ChatOptions.AdditionalProperties` (`sdks/dotnet/src/AGUI.Hosting.AspNetCore/RunAgentInputExtensions.cs:48`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/RunAgentInputExtensions.cs:91`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/RunAgentInputExtensions.cs:95`).
- The SDK intentionally exposes protocol/MEAI conversion; it does not create or attach MAF `AgentSession` objects.

## What remains MAF-side
MAF owns `Workflow.AsAgent()`/`AsAIAgent()`, workflow middleware invocation, and session propagation. The AG-UI adapter must pass the resolved `AgentSession` into the workflow-as-agent call, not just to inner agents.

## Proposal (once MAF consumes our packages)
1. In MAF's AG-UI endpoint, resolve the `AgentSession` from `RunAgentInput.ThreadId` before invoking a workflow-as-agent.
2. Pass that session through `RunStreamingAsync(..., session, ...)` so outer workflow middleware receives the same non-null session as inner agents.
3. Ensure workflow middleware can access the message list/session services populated by the AG-UI request conversion.
4. Add a regression test with workflow-level middleware asserting `session` is non-null and contains expected conversation services when invoked through AG-UI.
