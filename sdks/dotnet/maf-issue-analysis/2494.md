# Issue #2494 — AG-UI support for workflow as agent

- Repo: microsoft/agent-framework · [issue #2494](https://github.com/microsoft/agent-framework/issues/2494)
- Category: **AF-specific** — proposal for once MAF consumes our packages

## Summary

The issue asks whether a MAF workflow exposed as an AG-UI agent automatically maps workflow events back to AG-UI. The user can start the workflow from a CopilotKit/AG-UI client, but does not see streamed events after the workflow completes.

## What our packages already provide

`AsAGUIEventStreamAsync(...)` converts normal MEAI `ChatResponseUpdate` content to AG-UI events, including text and tool-call events (`src\AGUI.Hosting.AspNetCore\ChatResponseUpdateAGUIExtensions.cs:130`-`155`, `src\AGUI.Hosting.AspNetCore\ChatResponseUpdateAGUIExtensions.cs:158`-`185`). It also emits any `BaseEvent` set as `ChatResponseUpdate.RawRepresentation` directly (`src\AGUI.Hosting.AspNetCore\ChatResponseUpdateAGUIExtensions.cs:65`-`83`) and lets hosting code map custom workflow `AIContent` through `AGUIStreamOptions.MapContent(...)` (`src\AGUI.Hosting.AspNetCore\AGUIStreamOptions.cs:46`-`65`). Public workflow-friendly protocol events include `StepStartedEvent` and `StepFinishedEvent` (`src\AGUI.Abstractions\Events\StepStartedEvent.cs:6`-`13`, `src\AGUI.Abstractions\Events\StepFinishedEvent.cs:6`-`13`).

## What remains MAF-side

MAF owns workflow event semantics and the `WorkflowAsAgent` adapter. Our SDK cannot know which workflow events represent steps, activities, handoffs, final output, or errors, and it cannot make a workflow emit `ChatResponseUpdate` instances unless MAF's adapter translates them.

## Proposal (once MAF consumes our packages)

1. Add a MAF workflow-to-MEAI bridge for `WorkflowAsAgent` that turns workflow output into `ChatResponseUpdate` text/tool updates where applicable.
2. For workflow lifecycle/progress events, emit public AG-UI events (`StepStartedEvent`, `StepFinishedEvent`, `ActivitySnapshotEvent`, `CustomEvent`, etc.) by assigning them to `ChatResponseUpdate.RawRepresentation`.
3. Allow endpoint authors to extend the mapping with `AGUIStreamOptions.MapContent(...)` for workflow-specific event/content types.
4. Document that AG-UI support for workflows is not automatic at the raw workflow event level; the MAF adapter must translate workflow events into MEAI updates or explicit AG-UI `BaseEvent`s.
