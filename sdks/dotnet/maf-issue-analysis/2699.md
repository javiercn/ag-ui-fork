# Issue #2699 — Multi-turn parallel tool calls replay produces invalid OpenAI history

- Repo: microsoft/agent-framework · [issue #2699](https://github.com/microsoft/agent-framework/issues/2699)
- Category: **Integration-pkg — gap (validation test added, confirmed failing)**

## Summary
When a client (e.g. `@ag-ui/client`) represents parallel tool calls as **separate** assistant
messages (one tool call each), reconstructing OpenAI chat history one-to-one yields an invalid
sequence: `assistant(callA), assistant(callB), tool(A), tool(B)` — OpenAI requires a single
assistant message carrying both tool calls before the tool results.

## Finding (our SDK)
`AGUIChatMessageExtensions.AsChatMessages` maps each `AGUIAssistantMessage` 1:1 to a
`ChatMessage` with no coalescing of adjacent tool-call-only assistant messages
(`src/AGUI.Abstractions/Extensions/AGUIChatMessageExtensions.cs:69-93`).

## Validation
- Test: `tests/AGUI.Abstractions.UnitTests/MafIssueAbstractionsValidationTests.cs` →
  `AsChatMessages_ParallelToolCalls_CoalescedIntoSingleAssistantMessage`
- Result: **FAIL → gap confirmed.** Two consecutive single-tool-call assistant messages
  produce two assistant `ChatMessage`s instead of one coalesced message. Marked
  `[Fact(Skip=...)]`; un-skip when the gap is closed.

## Proposed step (not implemented)
Coalesce adjacent assistant messages that contain only tool calls (no text) into a single
assistant `ChatMessage` carrying all `FunctionCallContent`s, so the reconstructed history is
valid. Confirm the exact coalescing rule against the AG-UI/OpenAI history contract before
implementing.

## Relationship to the parallel-tool-results fix
This issue is a **separate concern** from the parallel-tool-**results** bug fixed in
`parallel-tool-calls.md`:

- **This issue (#2699)** is about parallel tool **calls** arriving inbound as *separate
  assistant messages* that must be coalesced into one assistant `ChatMessage` (the
  `AGUIAssistantMessage → ChatMessage` direction).
- **The parallel-tool-calls fix** is about parallel tool **results** in a single `ChatMessage`
  (`ChatRole.Tool`) being dropped on the *outbound* `AsAGUIMessages` path.

The outbound fix does not touch assistant-message coalescing, so this gap remains **open** and
its validation test (`AsChatMessages_ParallelToolCalls_CoalescedIntoSingleAssistantMessage`)
stays `[Fact(Skip=...)]`.
