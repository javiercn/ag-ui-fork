# Issue #2699 — Multi-turn parallel tool calls replay produces invalid OpenAI history

- Repo: microsoft/agent-framework · [issue #2699](https://github.com/microsoft/agent-framework/issues/2699)
- Category: **Integration-pkg — FIXED (coalescing in AsChatMessages)**

## Summary
When a client (e.g. `@ag-ui/client`) represents parallel tool calls as **separate** assistant
messages (one tool call each), reconstructing OpenAI chat history one-to-one yields an invalid
sequence: `assistant(callA), assistant(callB), tool(A), tool(B)` — OpenAI requires the assistant
`tool_calls` message to be immediately followed by its tool results. The reporter confirmed the
re-ordering originates in `@ag-ui/client`, so the server must reconstruct a provider-valid history.

## Fix
`AGUIChatMessageExtensions.AsChatMessages` now **accumulates a run of consecutive assistant
messages that carry tool calls** and emits them as a **single** assistant `ChatMessage` carrying
all `FunctionCallContent`s, before the tool results
(`src/AGUI.Abstractions/Extensions/AGUIChatMessageExtensions.cs:21`). This restores the canonical
shape our outbound `AsAGUIMessages` already produces (one assistant message with N tool calls).
The accumulation is **scoped/lazy**: only the current run is buffered, and legitimate sequential
flows (`assistant(call)→tool(result)→assistant(call)`) are never adjacent, so they are untouched.

## Validation
`tests/AGUI.Abstractions.UnitTests/MafIssueAbstractionsValidationTests.cs` (all **PASS**):
- `AsChatMessages_ParallelToolCalls_CoalescedIntoSingleAssistantMessage` — split calls merge into one.
- `AsChatMessages_ParallelToolCalls_FollowedByResults_ProducesValidOrder` — `assistant(tc_1,tc_2),
  tool(tc_1), tool(tc_2)` (provider-valid order).
- `AsChatMessages_SequentialToolCalls_NotMerged` — legitimate sequential calls are left intact.

Full suite green after the change: Abstractions 173 / Client 102 / Hosting 101 unit, 62 integration
(no baseline regressions — our own clients emit a single multi-call assistant message, so the
coalescing is a no-op for them and only triggers on the split pattern).

## Relationship to the parallel-tool-results fix
Distinct from the parallel-tool-**results** fix in `parallel-tool-calls.md`:
- **This issue (#2699)** = parallel tool **calls** arriving inbound as *separate assistant
  messages* → coalesced in `AsChatMessages` (`AGUIAssistantMessage → ChatMessage`).
- **Parallel-tool-calls fix** = parallel tool **results** in one `ChatMessage(Tool)` being dropped
  on the *outbound* `AsAGUIMessages` path.
