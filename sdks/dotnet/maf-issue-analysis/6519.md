# Issue #6519 — Make AG-UI hosting (MapAGUI) transport-extensible (currently SSE-only)

- Repo: microsoft/agent-framework · [issue #6519](https://github.com/microsoft/agent-framework/issues/6519)
- Category: **Core capability already present (user owns delivery); optional ergonomic transport API + protobuf/WebSocket parity**

## Summary
The AG-UI spec is transport-agnostic (SSE, WebSocket, HTTP binary, custom), but the .NET
hosting only ships an SSE endpoint, with no abstraction to plug in other server transports.

## Finding (our SDK) — core need already met by design
We separate event *production* from delivery: `AsAGUIEventStreamAsync` returns
`IAsyncEnumerable<BaseEvent>` independent of any wire format
(`src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs`), and the **consumer owns the
endpoint handler** (samples wrap it in `TypedResults.ServerSentEvents(...)` in `AGUIEndpoint.cs`).
Crucially, we have **no `internal sealed AGUIServerSentEventsResult`** — the exact blocker #6519
cites ("the SSE result type is internal sealed, cannot be reused/substituted/extended") does
**not** exist in our SDK. A consumer can already deliver the same event stream via WebSocket,
NDJSON, or Azure SignalR by writing their own endpoint that consumes `AsAGUIEventStreamAsync`.
The client side already has the `IAGUITransport` seam (`src/AGUI.Client/IAGUITransport.cs`).

So transport-agnosticism is **achievable today** without forking anything. What is missing is the
*ergonomic* turnkey API (a `MapAGUI(..., transport)` overload + public `IAGUIServerTransport`)
and real **non-SSE transport implementations** for parity with the TS SDK.

## Transport parity vs the TypeScript SDK (research: `transport-research` agent)
TS has exactly **two production transports** (both over one HTTP POST in `HttpAgent`):
- **HTTP SSE** — default; `Accept: text/event-stream`. **We have this** (client `AGUIHttpTransport`
  via `System.Net.ServerSentEvents`; server `TypedResults.ServerSentEvents`).
- **HTTP binary/protobuf** — opt-in; media type `application/vnd.ag-ui.event+proto`; wire =
  4-byte big-endian length prefix + protobuf bytes; package `@ag-ui/proto`
  (`sdks/typescript/packages/proto/src/proto/*.proto`). **We are missing this** on both client
  and server (no `Google.Protobuf`/proto codegen in the .NET repo).
- **WebSocket** — real but **community-only** (Cloudflare Agents, JSON text frames, proprietary
  vocabulary), not in core `@ag-ui/client`. No standardized AG-UI WebSocket sub-protocol.
- **NDJSON** — community **server helper** only; no TS client parser.
- **Webhooks / push & resumable** — **theoretical only** in TS (capability flags, no impl;
  aws-strands advertises `resumableStreams: false`).

Notably our SDK is **ahead** of TS on the client abstraction: TS has no transport interface
(transport is implicit in each `AbstractAgent.run()`), while we already have `IAGUITransport`.
`TransportCapabilities` (`src/AGUI.Abstractions/Capabilities/TransportCapabilities.cs`) already
models `Streaming`/`Websocket`/`HttpBinary`/`PushNotifications`/`Resumable` — no schema change needed.

## Validation
No automated test — extensibility/feature request, not a behavioral bug.

## Proposed step (not implemented) — prioritized
1. **(P1) Protobuf transport** (real parity gap with TS): client `AGUIProtoTransport : IAGUITransport`
   (opt-in `Accept: application/vnd.ag-ui.event+proto`, decode `[4-byte len][proto]` via
   `Google.Protobuf`, AOT-safe) + a server binary writer. Requires proto codegen from the existing
   `.proto` files. Keep **SSE the default** for interop with all TS/Python servers.
2. **(P1) Server delivery seam** `IAGUIServerTransport.DeliverAsync(IAsyncEnumerable<BaseEvent>,
   HttpContext, CancellationToken)` with an SSE default impl + a content-negotiating impl
   (mirror aws-strands: explicit proto Accept → proto; `*/*`/absent → SSE), plus a
   `MapAGUI(..., transport)` overload. `AsAGUIEventStreamAsync` needs **zero changes**.
3. **(P2) WebSocket transport** client `AGUIWebSocketTransport : IAGUITransport`
   (`ClientWebSocket`) + `app.UseWebSockets()` server delivery; document the JSON-text-frame
   framing (the spec doesn't standardize a WS sub-protocol).
4. **(skip) NDJSON / webhooks / resumable** — theoretical or community-only in TS; defer.

This is **building blocks**, consistent with the user's intent: let our client support these
transports and give the server the seams to deliver them, matching TS's real capabilities.
