# Issue #3002 — Workflow as AG-UI agent does not recognise client-side tools

- Repo: microsoft/agent-framework · [issue #3002](https://github.com/microsoft/agent-framework/issues/3002)
- Category: **AF-specific** — proposal for once MAF consumes our packages

## Summary

The issue reports that an Agent Framework workflow registered with `AddAsAIAgent()` and then exposed through `MapAGUI` does not call AG-UI client-side tools. The same endpoint receives tool definitions from an `AGUIChatClient` client, but the workflow-as-agent path never recognizes or invokes the `update_interface` tool.

## What our packages already provide

`RunAgentInput` has a public `Tools` property for AG-UI request tools (`src\AGUI.Abstractions\Context\RunAgentInput.cs:38`). `RunAgentInputExtensions.ToChatRequestContext` converts `input.Tools` to MEAI tools (`src\AGUI.Hosting.AspNetCore\RunAgentInputExtensions.cs:48`-`49`) and installs those tools into `ChatOptions.Tools` through the approval-flow pipeline (`src\AGUI.Hosting.AspNetCore\RunAgentInputExtensions.cs:91`-`99`, `src\AGUI.Hosting.AspNetCore\RunAgentInputExtensions.cs:177`-`192`). `ChatRequestContext.ChatOptions` is public and documented as already carrying client tools (`src\AGUI.Hosting.AspNetCore\ChatRequestContext.cs:57`-`61`).

## What remains MAF-side

The missing piece is in MAF's workflow-as-agent bridge, not in the AG-UI wire conversion. MAF must ensure the `ChatOptions.Tools` produced by the AG-UI endpoint survive the `AIAgent` → workflow → executor/inner-agent path and are made available wherever the workflow chooses tools. If a workflow executor drops `AgentRunOptions`, recreates `ChatOptions`, or invokes child agents without forwarding tools, AG-UI frontend tools cannot work.

## Proposal (once MAF consumes our packages)

1. In MAF `MapAGUI`, adapt the request with `RunAgentInput.ToChatRequestContext(...)` and pass `ctx.ChatOptions` into the selected `AIAgent`/workflow run options without rebuilding tools.
2. In `WorkflowAsAgent` / `AddAsAIAgent`, preserve `ChatClientAgentRunOptions.ChatOptions.Tools` when invoking workflow executors and any nested chat-client agents.
3. Add a regression test using a workflow-as-agent endpoint and a frontend tool supplied in `RunAgentInput.Tools`; assert the model sees the tool definition and that client-tool approval/tool-call events are returned.
4. If a workflow cannot support per-request tools, fail early with an explicit diagnostic rather than silently dropping `ChatOptions.Tools`.
