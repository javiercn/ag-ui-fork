# Issue #4342 — AGUIToolMessage to ChatMessage loses MessageId

- Repo: microsoft/agent-framework · [issue #4342](https://github.com/microsoft/agent-framework/issues/4342)
- Category: **Integration-pkg — already fixed/covered**

## Summary
The issue reports that converting an `AGUIToolMessage` to a `ChatMessage` creates a tool-result `ChatMessage` whose `MessageId` is `null` instead of preserving `AGUIToolMessage.Id`.

## Fix in our SDK
`src\AGUI.Abstractions\Extensions\AGUIChatMessageExtensions.cs:94-104` handles `AGUIToolMessage` by constructing the `FunctionResultContent` and setting `MessageId = message.Id` on the returned `ChatMessage`:

```csharp
yield return new ChatMessage(role, contents)
{
    MessageId = message.Id
};
```

## Validating test
Added (pending central run): `tests\AGUI.Abstractions.UnitTests\MafIssueFixedTests_4342.cs:9-26`, method `AsChatMessages_ToolMessage_PreservesMessageId`, validates that a tool message with `Id = "tool-msg-1"` maps to `ChatMessage.MessageId == "tool-msg-1"`.

## Notes
MAF should consume the `AGUI.Abstractions` message conversion helper so tool-result messages preserve their AG-UI message identity across the MEAI boundary.
