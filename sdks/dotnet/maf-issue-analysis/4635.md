# Issue #4635 — DataContent properties not propagated through AG-UI

- Repo: microsoft/agent-framework · [issue #4635](https://github.com/microsoft/agent-framework/issues/4635)
- Category: **Deprecated-workaround** — use the now-public AG-UI events

## Summary

The issue reports that a server-side `DataContent(JsonSerializer.SerializeToUtf8Bytes(content), "application/json") { Name = "ContentDetails" }` arrives at the AG-UI client without `Name` and other `DataContent` metadata. That pattern treats MEAI data content as a side channel for structured client data. In the old in-tree implementation, JSON `DataContent` was also used as a workaround for state by letting the transport reinterpret it as `STATE_SNAPSHOT`/`STATE_DELTA`.

## Why the old approach is deprecated

The `DataContent("application/json")` → `STATE_*` smuggling existed because the AG-UI event classes were internal (#2558). In this SDK, the protocol events are public: use `StateSnapshotEvent` or `StateDeltaEvent` for state, `CustomEvent` for named application-specific payloads, and `RawEvent` for opaque external payloads. `AsAGUIEventStreamAsync` emits any `BaseEvent` placed in `ChatResponseUpdate.RawRepresentation` directly, so there is no need for the transport to infer protocol events from MEAI `DataContent`.

## New approach — sample

```csharp
using System.Runtime.CompilerServices;
using System.Text.Json;
using AGUI.Abstractions;
using Microsoft.Extensions.AI;

internal sealed class ContentDetailsChatClient : DelegatingChatClient
{
    private readonly JsonSerializerOptions _jsonSerializerOptions;

    public ContentDetailsChatClient(IChatClient innerClient, JsonSerializerOptions jsonSerializerOptions)
        : base(innerClient)
    {
        _jsonSerializerOptions = jsonSerializerOptions;
    }

    public override async IAsyncEnumerable<ChatResponseUpdate> GetStreamingResponseAsync(
        IEnumerable<ChatMessage> messages,
        ChatOptions? options = null,
        [EnumeratorCancellation] CancellationToken cancellationToken = default)
    {
        await foreach (var update in base.GetStreamingResponseAsync(messages, options, cancellationToken).ConfigureAwait(false))
        {
            yield return update;
        }

        var contentDetails = new
        {
            id = "content-1",
            title = "Content generated",
            status = "ready"
        };

        yield return new ChatResponseUpdate
        {
            RawRepresentation = new CustomEvent
            {
                Name = "ContentDetails",
                Value = JsonSerializer.SerializeToElement(contentDetails, _jsonSerializerOptions)
            }
        };

        var state = new { content = contentDetails };
        yield return new ChatResponseUpdate
        {
            RawRepresentation = new StateSnapshotEvent
            {
                Snapshot = JsonSerializer.SerializeToElement(state, _jsonSerializerOptions)
            }
        };

        yield return new ChatResponseUpdate
        {
            RawRepresentation = new StateDeltaEvent
            {
                Delta = JsonSerializer.SerializeToElement(new[]
                {
                    new { op = "replace", path = "/content/status", value = "displayed" }
                }, _jsonSerializerOptions)
            }
        };
    }
}
```

## Notes

Do **not** port the `DataContent` metadata propagation or `DataContent("application/json")` → `STATE_*` magic mapping as an AG-UI feature in the new packages. If the client needs named structured data, emit `CustomEvent { Name = ..., Value = ... }`; if it needs state, emit `StateSnapshotEvent`/`StateDeltaEvent`; if it needs opaque pass-through, emit `RawEvent`.
