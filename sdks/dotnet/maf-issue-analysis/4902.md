# Issue #4902 — Multi-agent AG-UI events do not identify the executing agent

- Repo: microsoft/agent-framework · [issue #4902](https://github.com/microsoft/agent-framework/issues/4902)
- Category: **AF-specific** — proposal for once MAF consumes our packages

## Summary
In GroupChat/handoff workflows, AG-UI clients receive streaming text but cannot tell which agent produced each message. The issue asks MAF to surface the active agent name during multi-agent execution.

## What our packages already provide
- The AG-UI message model includes an optional `name` field (`sdks/dotnet/src/AGUI.Abstractions/Messages/AGUIMessage.cs:19`).
- `TextMessageStartEvent` exposes that `name` field on streamed text (`sdks/dotnet/src/AGUI.Abstractions/Events/TextMessageStartEvent.cs:17`).
- `AsAGUIEventStreamAsync` already passes `ChatResponseUpdate.AuthorName` through to `TextMessageStartEvent.Create(...)` (`sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:145`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:148`).
- Step events also exist for richer handoff UX (`sdks/dotnet/src/AGUI.Abstractions/Events/AGUIEventTypes.cs:12`, `sdks/dotnet/src/AGUI.Abstractions/Events/StepStartedEvent.cs:11`).

## What remains MAF-side
Our SDK cannot infer MAF workflow speaker identity. MAF owns GroupChat, handoff routing, workflow execution events, and the point where an active `Agent` name can be attached to updates.

## Proposal (once MAF consumes our packages)
1. In MAF workflow-to-MEAI streaming adapters, set `ChatResponseUpdate.AuthorName` to the current agent's stable display/name before yielding text updates.
2. For control-transfer events, optionally emit `new StepStartedEvent { StepName = agentName }` and `StepFinishedEvent` as `ChatResponseUpdate.RawRepresentation`; our converter emits raw `BaseEvent` values directly.
3. Ensure handoff and GroupChat managers use the same agent identifier for `AuthorName` and step names so UI labels remain stable.
4. Add MAF tests for two-agent GroupChat and handoff workflows verifying `TEXT_MESSAGE_START.name` and optional `STEP_*` events.
