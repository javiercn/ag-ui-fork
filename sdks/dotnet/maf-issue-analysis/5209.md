# Issue #5209 — Public AG-UI conversion API for multi-agent orchestration

- Repo: microsoft/agent-framework · [issue #5209](https://github.com/microsoft/agent-framework/issues/5209)
- Category: **Integration-pkg — already fixed/covered**

## Summary
The issue reports that MAF's AG-UI conversion types and helpers were internal, blocking custom multi-agent orchestrators from constructing or merging AG-UI event streams.

## Fix in our SDK
The protocol model is public: `BaseEvent` is public (`src/AGUI.Abstractions/Events/BaseEvent.cs:11`), concrete event classes are public (`src/AGUI.Abstractions/Events/RunStartedEvent.cs:6`, `src/AGUI.Abstractions/Events/TextMessageStartEvent.cs:6`, `src/AGUI.Abstractions/Events/ToolCallResultEvent.cs:9`, `src/AGUI.Abstractions/Events/MessagesSnapshotEvent.cs:7`), and `AGUIEventTypes` constants are public (`src/AGUI.Abstractions/Events/AGUIEventTypes.cs:7-34`). Hosting exposes the conversion API as `public static ... AsAGUIEventStreamAsync(...)` returning `IAsyncEnumerable<BaseEvent>` (`src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:36-39`). The public API file also lists these surfaces (`src/AGUI.Abstractions/PublicAPI.Unshipped.txt:432-501`, `src/AGUI.Hosting.AspNetCore/PublicAPI.Unshipped.txt:7-8`).

## Validating test
Existing test: `tests/AGUI.Hosting.AspNetCore.UnitTests/ChatResponseUpdateAGUIExtensionsTest.cs:92` (`ExplicitRunStartedEvent_PassedThrough_Directly`) validates a caller-provided public `RunStartedEvent` passes through conversion; the helper calls `updates.AsAGUIEventStreamAsync(...)` at `tests/AGUI.Hosting.AspNetCore.UnitTests/ChatResponseUpdateAGUIExtensionsTest.cs:1349`.

## Notes
MAF inherits a public event hierarchy and stream conversion primitive by consuming `AGUI.Abstractions` and `AGUI.Hosting.AspNetCore`, so custom orchestration code can construct `BaseEvent` subtypes and pipe converted agent streams without reimplementing the protocol.
