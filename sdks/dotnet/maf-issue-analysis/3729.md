# Issue #3729 — Multimodal user message content arrays crash endpoint binding

- Repo: microsoft/agent-framework · [issue #3729](https://github.com/microsoft/agent-framework/issues/3729)
- Category: **Integration-pkg — already fixed/covered**

## Summary
The issue reports that ASP.NET Core AG-UI endpoints fail JSON binding when a user message has `content` as an array of input content objects, such as text plus image/binary content, because the implementation expects `content` to be a string.

## Fix in our SDK
`src\AGUI.Abstractions\Messages\AGUIMessageJsonConverter.cs:67-108` accepts user-message `content` as either a string or an array and deserializes array elements by input-content discriminator, including `text`, `image`, `audio`, `video`, `document`, and `binary`.

The MEAI mapping also supports multimodal inputs: `src\AGUI.Abstractions\Extensions\AGUIChatMessageExtensions.cs:27-67` maps `AGUITextInputContent` to `TextContent` and `AGUIBinaryInputContent` to `UriContent` or `DataContent`, preserving the `filename` additional property.

## Validating test
Added (pending central run): `tests\AGUI.Abstractions.UnitTests\MafIssueFixedTests_3729.cs:11-52`, method `RunAgentInput_MultimodalUserMessageContentArray_DeserializesAndMapsToChatContents`, deserializes a `RunAgentInput` with a user `content` array and asserts it maps to `TextContent` plus `DataContent`.

## Notes
MAF should use the `AGUI.Abstractions` message types and converters when binding AG-UI requests; the converter handles spec-compliant content arrays before hosting code converts to `ChatMessage`.
