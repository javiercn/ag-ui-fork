# Issue #5587 — AGUI client crashes on non-JSON TOOL_CALL_RESULT content

- Repo: microsoft/agent-framework · [issue #5587](https://github.com/microsoft/agent-framework/issues/5587)
- Category: **Integration-pkg — already fixed/covered**

## Summary
The issue reports that a client receiving `TOOL_CALL_RESULT` with plain text such as `Transferred.` attempted JSON deserialization and crashed with `JsonException`.

## Fix in our SDK
The client converter does not parse `ToolCallResultEvent.Content` as JSON. It creates `FunctionResultContent` directly from the string content (`src/AGUI.Client/Internal/EventStreamConverter.cs:255-258`). The event type itself stores `Content` as `string` (`src/AGUI.Abstractions/Events/ToolCallResultEvent.cs:20-21`). On the hosting side, string function results are also preserved as strings rather than JSON-wrapped (`src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:383-390`).

## Validating test
Added (pending central run): `tests/AGUI.Client.UnitTests/MafIssueFixedTests_5587.cs:11` (`AGUIChatClient_ToolCallResultWithPlainTextContent_DoesNotParseAsJson`) validates a plain-text `TOOL_CALL_RESULT` becomes `FunctionResultContent.Result == "Transferred."` without JSON parsing.

## Notes
MAF's AG-UI client path inherits the non-JSON-safe behavior by consuming `AGUI.Client`; plain text tool results remain raw strings.
