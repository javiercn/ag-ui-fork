# Issue #4825 — Copilot permission.requested events are not AG-UI HITL events

- Repo: microsoft/agent-framework · [issue #4825](https://github.com/microsoft/agent-framework/issues/4825)
- Category: **AF-specific** — proposal for once MAF consumes our packages

## Summary
`GitHubCopilotAgent` receives Copilot SDK `permission.requested` events, including MCP tool approvals, but MAF's AG-UI path does not translate them into human-in-the-loop approval events. AG-UI clients therefore cannot approve or deny Copilot SDK tool executions.

## What our packages already provide
- The hosting converter maps MEAI `ToolApprovalRequestContent` to AG-UI `TOOL_CALL_START`, `TOOL_CALL_ARGS`, and `TOOL_CALL_END` events (`sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:234`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:247`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:250`).
- For server-owned approvals, it then emits `RUN_FINISHED` with an AG-UI interrupt containing approval metadata (`sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:271`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:273`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:371`).
- Custom MAF content can also be converted through `AGUIStreamOptions.MapInterrupt(...)` or `MapContent(...)` (`sdks/dotnet/src/AGUI.Hosting.AspNetCore/AGUIStreamOptions.cs:38`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/AGUIStreamOptions.cs:59`).

## What remains MAF-side
MAF owns `GitHubCopilotAgent`, Copilot SDK `SessionConfig.OnPermissionRequest`, and the callback needed to resume or deny the Copilot permission. Our SDK does not know Copilot SDK event shapes (`shell`, `write`, `read`, `mcp`, etc.) or call `session.respondToPermission()`.

## Proposal (once MAF consumes our packages)
1. In `GitHubCopilotAgent`, translate each Copilot SDK `permission.requested` event into either MEAI `ToolApprovalRequestContent` (preferred for tool-like permissions) or `InterruptRequestContent` with a structured response schema.
2. Include Copilot metadata (`kind`, MCP server/tool name, args, command/path/url) in the interrupt metadata or tool call arguments.
3. When the AG-UI client resumes, read the `RunAgentInput.Resume` entries through `ToChatRequestContext(...)` and route the user's decision back to Copilot SDK `OnPermissionRequest`/`respondToPermission()`.
4. Keep `PermissionHandler.ApproveAll` as an explicit opt-in only; default AG-UI hosting should surface approvals when the Copilot session requests them.
