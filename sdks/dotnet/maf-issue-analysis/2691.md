# Issue #2691 — DevUI workflows require complex Chat Protocol and hide workflow output

- Repo: microsoft/agent-framework · [issue #2691](https://github.com/microsoft/agent-framework/issues/2691)
- Category: **AF-specific** — proposal for once MAF consumes our packages

## Summary

The issue reports a DevUI parity gap: simple/custom .NET workflows require chat-protocol and `TurnToken` plumbing, and `WorkflowOutputEvent` data from `YieldOutputAsync()` is not visible in DevUI. Python workflows display yielded output directly with much less boilerplate.

## What our packages already provide

For AG-UI streams, unmapped framework content can be converted through `AGUIStreamOptions.MapContent(...)` (`src\AGUI.Hosting.AspNetCore\AGUIStreamOptions.cs:46`-`65`) or emitted as a first-class `BaseEvent` through `ChatResponseUpdate.RawRepresentation` (`src\AGUI.Hosting.AspNetCore\ChatResponseUpdateAGUIExtensions.cs:65`-`83`). The protocol already includes displayable text events (`src\AGUI.Abstractions\Events\AGUIEventTypes.cs:14`-`16`), workflow step events (`src\AGUI.Abstractions\Events\AGUIEventTypes.cs:12`-`13`), and activity events (`src\AGUI.Abstractions\Events\AGUIEventTypes.cs:30`-`31`).

## What remains MAF-side

DevUI's `WorkflowOutputEvent` mapping, `TurnToken` contract, workflow invocation model, and Python/.NET parity decisions are all MAF concerns. Our SDK can carry AG-UI events once MAF produces them, but it does not own DevUI's response-item mapper or workflow executor ergonomics.

## Proposal (once MAF consumes our packages)

1. Update MAF DevUI's `AgentRunResponseUpdateExtensions` equivalent to handle `WorkflowOutputEvent` explicitly: extract string/text/`ChatMessage` content and serialize objects to visible text or structured output.
2. Add tests for `YieldOutputAsync(string)`, `YieldOutputAsync(ChatMessage)`, and object output so DevUI no longer emits empty content arrays.
3. Consider a DevUI workflow-hosting path that invokes custom workflows directly without requiring every executor to implement chat-protocol `TurnToken` forwarding.
4. For AG-UI endpoints over workflows, reuse the same extraction logic to yield `TextMessage*`, `Step*`, `Activity*`, or `CustomEvent` instances via `RawRepresentation` or `MapContent(...)`.
