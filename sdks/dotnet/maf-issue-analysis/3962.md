# Issue #3962 — MapAGUI reuses the same messageId for consecutive TOOL_CALL_RESULT events

- Repo: microsoft/agent-framework · [issue #3962](https://github.com/microsoft/agent-framework/issues/3962)
- Category: **Integration-pkg — resolved as by-design (regression guard added)**

## Summary
Each `TOOL_CALL_RESULT` event is given a `messageId` equal to its `toolCallId`. The issue asks
whether this is a bug, since a message id and a tool-call id are distinct concepts in the AG-UI
spec.

## Finding (our SDK)
This is **intentional and correct**. A tool result is identified by its `toolCallId` in BOTH
conversion directions, which keeps the identity deterministic and round-trippable:

- **Response side** (`.NET → AG-UI`): `ToolCallResultEvent.Create` sets
  `MessageId = toolCallId` (`src/AGUI.Hosting.AspNetCore/AGUIEventExtensions.cs:109`):
  ```csharp
  new() { ToolCallId = toolCallId, MessageId = toolCallId, Content = result, RawEvent = rawEvent };
  ```
- **Outbound request side** (`.NET → AG-UI`, history round-trip): `AsAGUIMessages` keys each
  `AGUIToolMessage.Id` on the call id as well
  (`src/AGUI.Abstractions/Extensions/AGUIChatMessageExtensions.cs:212-217`):
  ```csharp
  yield return new AGUIToolMessage
  {
      Id = functionResult.CallId,
      ToolCallId = functionResult.CallId,
      Content = SerializeFunctionResult(functionResult, message.Text)
  };
  ```

The AG-UI `ToolMessageSchema` requires both an `id` and a single `toolCallId`. The wire
`messageId` is otherwise dropped/echoed by clients, so deriving it from the (unique,
deterministic) `toolCallId` is the most stable choice and keeps record/replay baselines stable.
The TS reference client behaves equivalently.

## Validation
- Test: `tests/AGUI.Hosting.AspNetCore.UnitTests/MafIssueHostingValidationTests.cs` →
  `ToolCallResult_MessageId_EqualsToolCallId_ByDesign`
- Result: **PASS.** Asserts `resultEvent.MessageId == resultEvent.ToolCallId` as a regression
  guard documenting the intentional design.

## Decision
No change. Generating a fresh per-message id would break the deterministic identity that both
directions rely on (and that parallel-tool-result preservation depends on — see
`parallel-tool-calls.md`). Closed as by-design.
