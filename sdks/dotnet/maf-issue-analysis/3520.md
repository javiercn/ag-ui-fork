# Issue #3520 — Expose USAGE details (tokens) to the front end

- Repo: microsoft/agent-framework · [issue #3520](https://github.com/microsoft/agent-framework/issues/3520)
- Related: #3684, #3752 (same topic)
- Category: **Integration-pkg — by design (extensibility), not a default mapping**

## Summary
Token-usage details produced by the model are not surfaced to the AG-UI client out of the box.

## Resolution — by design, via extensibility
AG-UI has no standard usage event, and the framework should **not** impose a usage
representation by default. Usage is surfaced through extensibility, so each application chooses
its own shape. The **preferred** path is a delegating chat client/agent; a content mapper is a
secondary seam aimed at framework integrators:

1. **(Preferred) Wrap the `IChatClient` / `AIAgent`** with a `DelegatingChatClient` that
   intercepts `UsageContent` and yields a `ChatResponseUpdate` whose `RawRepresentation` is a
   `CustomEvent`/`RawEvent`. The hosting layer streams any `BaseEvent` set as
   `RawRepresentation` directly (`ChatResponseUpdateAGUIExtensions.cs:66`). This is exactly
   what the shipped sample `samples/GettingStarted/Step06_RawEvents` does
   (`UsageRawEventsChatClient` turns `UsageContent` into a `RawEvent`).
2. **(For framework integrators) Register a content mapper** via
   `AGUIStreamOptions.MapContent(...)` (`src/AGUI.Hosting.AspNetCore/AGUIStreamOptions.cs:59`).
   This hosting-boundary seam is geared toward frameworks like MAF that own the endpoint
   wiring, rather than app developers.

`UsageContent` falling through the `default` content case
(`ChatResponseUpdateAGUIExtensions.cs:309`) is therefore the intended behavior, not a gap.

## Snippet — preferred (delegating chat client)
```csharp
internal sealed class UsageRawEventsChatClient(IChatClient inner, JsonSerializerOptions json)
    : DelegatingChatClient(inner)
{
    public override async IAsyncEnumerable<ChatResponseUpdate> GetStreamingResponseAsync(
        IEnumerable<ChatMessage> messages, ChatOptions? options = null,
        [EnumeratorCancellation] CancellationToken ct = default)
    {
        await foreach (var update in base.GetStreamingResponseAsync(messages, options, ct))
        {
            yield return update;

            foreach (var usage in update.Contents.OfType<UsageContent>())
            {
                // Emit usage as an AG-UI RawEvent (or CustomEvent) — the hosting layer streams
                // any BaseEvent set as RawRepresentation verbatim.
                yield return new ChatResponseUpdate
                {
                    RawRepresentation = new RawEvent
                    {
                        Source = "usage",
                        Event = JsonSerializer.SerializeToElement(usage.Details, json),
                    },
                };
            }
        }
    }
}
```
(For framework integrators, the equivalent at the hosting boundary is
`options.MapContent(c => c is UsageContent u ? new[] { new CustomEvent { Name = "usage", ... } } : null)`.)

## Validation
By design — no dedicated test (per our rule, by-design/extensibility outcomes are captured as a
snippet, not a test). The wrapping-client mechanism is exercised end-to-end by the shipped
Step06 sample tests (`tests/.../Samples/GettingStarted/Step06_RawEventsTest.cs`) and the Step06
cross-language test.

## Proposed step
No framework change. Document the recipe above (wrap the chat client — see Step06 — or a
`MapContent` mapper for framework integrators).
