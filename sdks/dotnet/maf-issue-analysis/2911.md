# Issue #2911 — DevUI freezes testing workflow with sub-workflow

- Repo: microsoft/agent-framework · [issue #2911](https://github.com/microsoft/agent-framework/issues/2911)
- Category: **AF-specific** — proposal for once MAF consumes our packages

## Summary

The issue reports that MAF DevUI freezes when testing a workflow that contains a bound sub-workflow executor. The same workflow runs outside DevUI, and removing the sub-workflow makes DevUI work, so the problem is in MAF DevUI/workflow execution or event handling rather than in the AG-UI protocol itself.

## What our packages already provide

For AG-UI endpoints, the SDK can surface framework-specific workflow events in two ways. A `ChatResponseUpdate.RawRepresentation` that is already a `BaseEvent` is emitted directly (`src\AGUI.Hosting.AspNetCore\ChatResponseUpdateAGUIExtensions.cs:65`-`83`). For custom `AIContent`, MAF can register `AGUIStreamOptions.MapContent(...)` to turn workflow/sub-workflow content into protocol events (`src\AGUI.Hosting.AspNetCore\AGUIStreamOptions.cs:46`-`65`), including public step events (`src\AGUI.Abstractions\Events\StepStartedEvent.cs:6`-`13`, `src\AGUI.Abstractions\Events\StepFinishedEvent.cs:6`-`13`).

## What remains MAF-side

DevUI is a MAF component and does not become correct merely because AG-UI protocol events exist. MAF must diagnose the DevUI freeze, ensure sub-workflow lifecycle/turn-token events are consumed, and decide how nested workflow progress is represented in DevUI and in any AG-UI endpoint.

## Proposal (once MAF consumes our packages)

1. In MAF DevUI, add a repro test with a parent workflow using `BindAsExecutor(...)` for a sub-workflow and verify the UI/event stream completes.
2. Fix the DevUI workflow runner so sub-workflow executor events and completion signals are drained instead of leaving the UI waiting indefinitely.
3. If exposing the same workflow via AG-UI, add a workflow-event bridge that emits `StepStartedEvent` / `StepFinishedEvent` through `ChatResponseUpdate.RawRepresentation` or an `AGUIStreamOptions.MapContent(...)` mapper.
4. Document the supported DevUI + workflow/sub-workflow execution pattern separately from AG-UI endpoint configuration.
