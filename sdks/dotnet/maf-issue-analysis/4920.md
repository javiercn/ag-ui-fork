# Issue #4920 — MapAGUI ignores session store and message author names

- Repo: microsoft/agent-framework · [issue #4920](https://github.com/microsoft/agent-framework/issues/4920)
- Category: **AF-specific** — proposal for once MAF consumes our packages

## Summary
MAF's `MapAGUI()` currently invokes an agent with `session: null`, so configured session stores are not used and each AG-UI turn starts as a fresh workflow run. The issue also notes that message author/agent names are not surfaced consistently for AG-UI clients.

## What our packages already provide
- `RunAgentInput` carries AG-UI `threadId`, which MAF can use as the conversation/session id (`sdks/dotnet/src/AGUI.Abstractions/Context/RunAgentInput.cs:16`).
- `ToChatRequestContext` stores the original `RunAgentInput` in `ChatOptions.AdditionalProperties[AGUIConstants.RunAgentInputKey]`, so downstream MAF components can recover `threadId`, `state`, `resume`, and forwarded props (`sdks/dotnet/src/AGUI.Hosting.AspNetCore/RunAgentInputExtensions.cs:91`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/RunAgentInputExtensions.cs:95`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/AGUIConstants.cs:16`).
- AG-UI messages have a `name` field (`sdks/dotnet/src/AGUI.Abstractions/Messages/AGUIMessage.cs:19`), and outgoing streaming text maps `ChatResponseUpdate.AuthorName` to `TEXT_MESSAGE_START.name` (`sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:145`, `sdks/dotnet/src/AGUI.Hosting.AspNetCore/ChatResponseUpdateAGUIExtensions.cs:148`).

## What remains MAF-side
Our SDK does not own MAF's `AIHostAgent`, `.WithSessionStore()`, `AgentSession`, or workflow session lifecycle. MAF must resolve/create the session from AG-UI `threadId` and must populate `ChatResponseUpdate.AuthorName` (or equivalent raw events) from workflow/agent identity.

## Proposal (once MAF consumes our packages)
1. In MAF's `MapAGUI` endpoint, call `input.ToChatRequestContext(...)` and read `context.Input.ThreadId` (or `ChatOptions.AdditionalProperties[AGUIConstants.RunAgentInputKey]`) as the conversation id.
2. Before `RunStreamingAsync`, call MAF's `AIHostAgent.GetOrCreateSessionAsync(conversationId)` when a session store is configured, and pass that session instead of `null`.
3. Treat client-supplied message history as input context, but prefer server session state for continuity when a session store is available.
4. When workflow/multi-agent updates identify a speaker, set `ChatResponseUpdate.AuthorName`; our stream converter will emit it as AG-UI `name`.
